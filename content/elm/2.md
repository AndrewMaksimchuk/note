# Elm strictly requires both the if and else branches

You cannot have an if block without an else in Elm.

## Why Elm Requires else

In Elm, if is an expression, not a statement. Every expression in Elm must evaluate to a single, concrete value.

Because every function and block must return a value:
- An if without an else would leave the code without a return value when the condition is False.
- Both the then branch and the else branch must evaluate to the same type.

```elm
-- Correct: Both branches exist and return the same type (String)
greeting : Bool -> String
greeting isLoggedIn =
    if isLoggedIn then
        "Welcome back!"

    else
        "Please log in."
```

## How to Handle Optional Behavior

If you want to perform an action or render something only under certain conditions (where you might typically use a single if in other languages), Elm uses explicit types or patterns:

1. Rendering Optional UI Elements

When working with HTML in Elm, you explicitly return an empty element or node when the condition isn't met:

```elm
viewNotification : Bool -> Html msg
viewNotification hasMessage =
    if hasMessage then
        div [] [ text "You have a new message!" ]

    else
        text "" -- Returns an empty text node when False
```

2. Optional Values (Maybe)

If a value might not exist, use Elm's Maybe type (Just value or Nothing):

```elm
getUserNickname : User -> String
getUserNickname user =
    case user.nickname of
        Just name ->
            name

        Nothing ->
            "Anonymous"
```
