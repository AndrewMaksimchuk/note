# Таблиця правил

Вона дозволяє описати поведінку програми через набір правил, а саму програму зробити універсальним механізмом, який ці правила читає та виконує.

Головна ідея: замість того щоб зашивати всі правила в код, ми зберігаємо їх окремо, у структурованому вигляді.

Розберімо на прикладі опалення будинку, а потім подивимося, як це працює в програмуванні.

1. Почнемо зі звичайного if/else

Уявімо систему керування опаленням із такими вимогами:
- якщо температура нижче 16 °C — нагрівання потрібне;
- якщо температура від 16 °C до 19 °C — нагрівання потрібне лише в комфортному режимі;
- якщо температура 19 °C або вище — нагрівання не потрібне;
- якщо активне технічне обслуговування — звичайне нагрівання заборонене.

Можна записати все це в коді:

```javascript
function decideHeating(temp, comfortMode, maintenance) {
  if (maintenance) {
    return "OFF";
  }

  if (temp < 16) {
    return "ON";
  }

  if (temp < 19 && comfortMode) {
    return "ON";
  }

  return "OFF";
}
```

Поки що все нормально. Але уяви, що правил не 4, а 40. Або що їх потрібно змінювати залежно від сезону.

Код поступово перетворюватиметься на велику систему умов, у якій складно знайти конфлікти та зрозуміти, яке правило має пріоритет.

2. Перетворимо умови на таблицю правил

Тепер спробуємо описати ті самі вимоги у вигляді таблиці.

Таблиця правил опалення
№	Умова	Дія
1	Обслуговування активне	Заборонити звичайне нагрівання
2	Температура нижче 16 °C	Увімкнути нагрівання
3	Температура від 16 °C до 19 °C та комфортний режим	Увімкнути нагрівання
4	Жодне правило не спрацювало	Не вмикати нагрівання

Це вже опис поведінки системи, який можна читати без знання JavaScript.

Проте поки що це просто таблиця документації. Щоб вона стала таблицею правил, яку програма виконує, потрібно домовитися про її структуру та написати механізм обробки.

3. Як виглядає таблиця правил у коді?

Можемо представити кожне правило як об'єкт JavaScript.

```
const rules = [
  {
    name: "maintenance",
    when: ({ maintenance }) => maintenance,
    action: "OFF"
  },
  {
    name: "very_cold",
    when: ({ temp }) => temp < 16,
    action: "ON"
  },
  {
    name: "comfort",
    when: ({ temp, comfortMode }) =>
      temp >= 16 && temp < 19 && comfortMode,
    action: "ON"
  }
];
```


Зверни увагу на три складові кожного правила:
- name — ідентифікатор правила;
- when — умова, за якої воно спрацьовує;
- action — результат, який воно задає.
А тепер створимо універсальний механізм, який перевіряє правила послідовно.

```
function evaluateRules(input, rules) {
  for (const rule of rules) {
    if (rule.when(input)) {
      return rule.action;
    }
  }

  return "OFF";
}
```

Використання:

```
const result = evaluateRules(
  {
    temp: 15,
    comfortMode: false,
    maintenance: false
  },
  rules
);

console.log(result); // "ON"
```

Ми винесли самі правила з алгоритму. Функція evaluateRules більше не знає нічого про температуру, комфортний режим чи обслуговування. Вона лише перевіряє умови й повертає дію першого правила, що спрацювало.

Оце вже суттєва зміна архітектури програми.

Важливо: порядок правил тут має значення, бо механізм зупиняється на першому збігу. У цьому прикладі правило обслуговування стоїть першим саме для того, щоб заборона мала пріоритет.
